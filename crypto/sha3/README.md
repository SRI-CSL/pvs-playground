# Keccak, SHA-3, and derived functions

`keccak` contains the 1600-bit permutation, streaming bit absorption, SHA3-224/256/384/512, and SHAKE128/256. `sp800_185` adds cSHAKE, KMAC and KMACXOF, TupleHash and TupleHashXOF, and ParallelHash and ParallelHashXOF. Input and output bits use the little-endian order within each Keccak octet. The SP 800-185 encoders use bounded integers for bit lengths. [FIPS 202](https://doi.org/10.6028/NIST.FIPS.202) · [SP 800-185](https://doi.org/10.6028/NIST.SP.800-185)

`keccak_p` implements Algorithms 1–7 for widths 25, 50, 100, 200, 400, 800 and 1600. The width argument is the logarithm of the lane size, from 0 through 6. Each state stores 25 unsigned 64-bit lanes in x+5y order and masks unused high bits at the boundary. `permute_f` selects the standard full-round count. `permute_p` accepts any positive 32-bit round count, including counts longer than Keccak-f. For longer sequences initialize `begin_p` with the total count modulo 255, then apply `advance_p` in 32-bit chunks.

Run `python3 validation/check.py sha3 keccak-p` to replay the proofs, translate to C, and execute the examples. Of the 29 permutation checks, 21 cover one round, the full count and seven additional rounds at each of the seven widths. Eight cases compare two complete permutations at each published XKCP width. The independent fixture generator implements the standard on individual Boolean coordinates and verifies the four designers’ transcripts before emitting test inputs. [Keccak designers’ intermediate values](https://github.com/XKCP/XKCP/tree/master/tests/TestVectors)

The typechecked, open theorems in `keccak_p_claims` state preservation of lane width, injectivity and surjectivity on canonical states, and agreement between the generic and optimized 1600-bit permutation and round constants. To regenerate the fixture, save the XKCP `KeccakF-<width>-IntermediateValues.txt` files as `f200.txt`, `f400.txt`, `f800.txt`, and `f1600.txt`, then run `python3 sha3/keccak_p_vectors.py --gzip <directory>`.
