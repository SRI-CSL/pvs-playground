# Random-bit generation

The SP 800-90A Rev. 1 state transitions cover Hash_DRBG, HMAC_DRBG and AES CTR_DRBG. The hash variants include the seven SHA-1/SHA-2 choices in Table 2 and the SHA-3 variants used by the construction layer. CTR_DRBG covers 128-, 192- and 256-bit AES keys, with and without the block-cipher derivation function. Generation accepts optional additional input, updates the internal state and enforces the reseed interval and the request limit. Instantiation and reseeding take supplied entropy and other input strings. Prediction resistance requires the caller to acquire fresh entropy and reseed before generating. [SP 800-90A Rev. 1 §§9–10](https://doi.org/10.6028/NIST.SP.800-90Ar1)

Run `python3 validation/check.py hash-drbg hmac hmac-reseed` and `python3 validation/check_aes.py ctr-drbg`. These replay the saved proofs and run generated C against NIST derandomized test cases, including reseeding, personalization, additional input, prediction-resistance sequences and both CTR derivation choices. [NIST DRBG test vectors](https://csrc.nist.gov/projects/cryptographic-algorithm-validation-program/random-number-generators)

The shared provider boundary in `crypto_prelude` supplies entropy and PRNG streams separately. Entropy-source claims, incoming entropy estimates and operational provider assurance require evidence for the actual deployed source.

## Entropy assessment

[entropy_assessment](entropy_assessment.pvs) brings together sequential and restart assessment. Its track selector requires the submitter’s IID claim, the sequential sample and both orderings of the restart sample to pass. It includes the conditioned binary sample when a non-vetted conditioner is selected. The non-IID estimator selects the minimum of the applicable §6.3 estimates. The restart procedure processes 1,000 rows of 1,000 observations, tests the largest row or column count against its binomial tail and applies the half-initial-entropy rejection rule.

The sample interface uses octets, with one through eight significant bits. For wider source words, `project` takes ranked positions in a 64-bit word. Source characterization and bit ranking are inputs supplied by the developer. [entropy_health](entropy_health.pvs) provides both continuous tests, cutoff calculation, a 1,024-sample startup gate, on-demand testing and a latched failure policy. [SP 800-90B §§3–6](https://csrc.nist.gov/pubs/sp/800/90/b/final)

Run `python3 validation/check_assessments.py entropy`. The fixture `rand1_short.bin.gz` contains the 10,000 symbols in the NIST entropy assessment tool’s `bin/rand1_short.bin`. It checks each of the ten estimators against the corresponding `cpp/selftest/refdata/rand1_short.res` value. The PVS equations use the quantile 2.576 printed in §6.3. The tests also cover published short examples, 10,000 shuffles on a short sequence, a million-symbol suffix and chi-square comparison, and full-size restart matrices. The attachment for the permutation compression statistic uses bzip2 at level five. [NIST reference code and fixtures](https://github.com/usnistgov/SP800-90B_EntropyAssessment)

## RBG constructions

[rbg_instances](rbg_instances.pvs) exposes RBG1, sub-DRBG, RBG2(P/NP), RBG3(XOR/RS), and root and non-root RBGC operations. Callers retain both returned states after a parent generates seed material. `seed_from_rbg` checks source type and strength and performs the mandatory source reseed for RBG1. `full_generate` uses source handles for already qualified randomness. [rbg_profiles](rbg_profiles.pvs) accepts a transcript with health, validation, source identity, physical status and conservative entropy credits in units of 1/256 bit. Its generation and conditioning operations return the next unused transcript position. Raw full-entropy requests require full credit on every included octet. Caller responsibilities include validating source independence and freshness, authorizing an alternate source within a tree, protecting transferred state and enforcing deployment-wide usage limits. [SP 800-90C §§2–7](https://csrc.nist.gov/pubs/sp/800/90/c/final)

Run `python3 validation/check_assessments.py constructions` for the current profiles. The smaller `rbg_constructions` and `rbg_tree` theories provide the existing HMAC_DRBG/SHA-256 interface and vectors. The new theorem statements await proof. Numerical claims use the shared binary64 interface and require a mathematical interpretation of its attachments.
