# RSA key generation

`rsa_primes` and `rsa_keygen` implement the random probable-prime construction in Appendix A.1.3 of [FIPS 186-5](https://csrc.nist.gov/pubs/fips/186-5/final). Profiles 0, 1, and 2 select the 2048-, 3072-, and 4096-bit moduli for which Table B.1 supplies Miller–Rabin counts. The additional theories implement the four other prime-generation methods in Appendices A.1.2 and A.1.4–A.1.6.

`generate(profile,e,pmod,qmod,high_assurance,stream)` returns the public modulus and exponent, two probable primes, canonical private exponent, and CRT exponents and coefficient. Enter the public exponent as a minimal unsigned big-endian octet string. Each optional mod-8 constraint is 0 for unrestricted odd candidates, or 1, 3, 5, or 7 for a particular residue. The high-assurance flag selects Table B.1’s security-strength error target. Clearing it selects the 2⁻¹⁰⁰ target.

The implementation checks the prime lower bounds by exact squaring and enforces prime separation, exponent coprimality, candidate retry limits, and the lower and upper bounds on the private exponent. Miller–Rabin uses independent draws, discarding bases outside the required interval. The application supplies a fresh, adequately instantiated DRBG stream through the shared PRNG attachment. Failure to obtain bytes, including exhaustion of the 32-bit stream offset, returns a failure record with empty fields. Generated-C execution, proof replay, and vector comparisons cover functional behavior. The application remains responsible for protecting and erasing private material.

`derive_from_factors` reconstructs a key from already screened factors. It uses fixed-width schoolbook multiplication, restoring division, binary GCD, and binary modular inversion from `crypto_prelude/crypto_integer_ops`. This entry point checks integer constraints and assumes the caller has established primality. The saved public-components theorem proves that successful reconstruction returns the input exponent, the encoded factors, and their product after the exponent, size, and separation checks. Further lemmas establish the accepted witness interval and the modular congruence from the exact private-exponent division equation.

`shawe_taylor` implements recursive provable-prime construction in B.6. It hashes the changing big-endian seed, applies deterministic trial division to the short base case, and checks the modular exponentiation and GCD certificate for each recursive prime. `rsa_provable` implements B.10 for both random provable primes (A.1.2) and provable primes with provable auxiliary factors (A.1.4). The four auxiliary lengths are all 1 for A.1.2. For A.1.4 supply lengths within Table A.1. `from_provable_seed` accepts a seed, and `generate_provable` obtains one through the common PRNG attachment. The minimum seed lengths are 28 octets for 2048-bit RSA and 32 octets for 3072- or 4096-bit RSA. The byte-string adapter supports seeds up to 4,096 octets.

`rsa_auxiliary` implements the CRT progression in B.9. For A.1.5 it constructs the auxiliary factors from the evolving Shawe–Taylor seed. For A.1.6 it selects odd starts of the required bit lengths, then searches in steps of two using the auxiliary Miller–Rabin counts from Table B.1. Both modes impose prime and start-value separation and optional mod-8 constraints. `generate_auxiliary` takes separate streams for candidate starts and primality-test witnesses, with a third seed stream for A.1.5. Supply fresh stream identifiers for each generation. All successful key-generation paths return the same key format. Arithmetic uses explicit word sizes. The seed-driven routines include a 32-bit attempt budget for repeated factor and pair constructions.

Run `python3 validation/check.py rsa-keygen` to replay the proofs, generate and compile C, and exercise the test corpus. The 15 NIST CRT projections check the modulus, reduced exponents, and CRT coefficient. The independently calculated inverse of the public exponent modulo the least common multiple gives the expected full private exponent. Five deterministic random-input transcripts also exercise the entire A.1.3 entry point, including rejected candidates and rejected witnesses. Those transcripts use the published factors as known-good candidates. The corpus includes an unavailable provider, an exhausted stream, equal factors, a strong pseudoprime, and an out-of-range Miller–Rabin base.

`acvp_inputs.py` converts the original NIST JSON to the bundled binary fixture. Its source `internalProjection.json` had SHA-256 digest `c60c35ae46078d194f738dbaa730893933044a6b90751fa99a567f172b6d4cf9`. [NIST ACVP RSA key-generation data](https://github.com/usnistgov/ACVP-Server/tree/master/gen-val/json-files/RSA-KeyGen-FIPS186-5)

Run `python3 validation/check.py rsa-provable rsa-auxiliary` for the alternative methods. The first fixture starts with NIST’s published seeds and checks both generated factors for A.1.2 and A.1.4. The second uses the published seeds or candidate starts, independently supplies deterministic test witnesses, and checks both generated factors for A.1.5 and A.1.6. `provable_inputs.py` and `auxiliary_inputs.py` regenerate the two fixtures from the same NIST projection. Their `--sample` option selects the first case from each group.

The proof-only `rsa_key_claims` theory decodes the returned octets into mathematical integers. Its typechecked theorem states the modulus product, private-exponent inverse and bounds, and all three CRT relationships. The general proof connecting every arithmetic output to these integer equations is open.

`provable_prime_claims` states the soundness and width of the recursive Shawe–Taylor output, primality of the factors in the provable-key frontend, and the CRT progression’s auxiliary-factor and mod-8 congruences. These general claims also typecheck and remain open.
