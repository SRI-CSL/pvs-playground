# ECDSA and elliptic-curve Diffie–Hellman

`nist_prime_curves` stores the domain parameters for P-192, P-224, P-256, P-384 and P-521. Each integer uses 32-bit little-endian limbs of the curve's width. `prime_curve` implements projective addition, doubling, scalar multiplication, affine conversion, public-key checks and cofactor DH. The ECDH result encodes the affine x-coordinate in the field's full octet width. [SP 800-186 §3.2](https://doi.org/10.6028/NIST.SP.800-186) · [SP 800-56A Rev. 3](https://doi.org/10.6028/NIST.SP.800-56Ar3)

`ecdsa` accepts a digest and an explicit private scalar and nonce for signing. Its verification operation accepts a public point, digest and signature scalars. `ecdsa_signing` adds an HMAC_DRBG-based deterministic frontend, checked single-draw random signing and key generation, and SHA-2 message hashing. `ecdsa_extra_bits` implements the alternative N+64-bit reduction for the four active curves and message signing/verification with the SHA-2, SHA-3 and SHAKE digest encodings. A rejected random candidate can be retried with a fresh stream. Deterministic candidate retries accept an explicit bound. The generation frontend accepts P-224 and larger. P-192 is present for legacy verification and arithmetic tests. [FIPS 186-5 §§6.2–6.4 and Appendix A](https://doi.org/10.6028/NIST.FIPS.186-5)

Run `python3 validation/check.py ec ec-signing`. The generated C checks the private scalar, public coordinates, signing nonce and both signature components for the SHA-256 “sample” cases, plus altered-message rejection and a separate ECDH result on each curve. The signed-message frontend reproduces the RFC signature with deterministic and sampled nonces on all four active curves. [RFC 6979 Appendix A.2](https://www.rfc-editor.org/rfc/rfc6979#appendix-A.2)
