# Secure Hash Standard

`secure_hash.pvs` implements SHA-1, SHA-224, SHA-256, SHA-384, SHA-512, SHA-512/224 and SHA-512/256. The functions named for each hash take a Prelude byte string and return a byte string of the digest's specified length. The corresponding `_bits` functions accept an additional octet and a count from zero to seven, using that many of its most significant bits. The single-call input is bounded by the Prelude byte string type. Compression functions and initial state constants are also exposed. SHA-1 is included for legacy uses. [FIPS 180-4](https://doi.org/10.6028/NIST.FIPS.180-4)

Run `python3 validation/check.py sha2 sha2-cavp` from the crypto directory. The first suite replays saved proof obligations and checks the seven published “abc” digests in generated C. The proofs include the sufficiency and minimality of both padded block counts. The second suite compares generated C with 105 NIST SHAVS bit-oriented cases. The offline fixture contains 15 rows from each ShortMsg response file, covering the empty message, one through nine bits, the length-field padding boundary and full-block boundaries. [NIST example digests](https://csrc.nist.gov/projects/cryptographic-standards-and-guidelines/example-values) · [SHAVS vectors](https://csrc.nist.gov/projects/cryptographic-algorithm-validation-program/secure-hashing)

`sha2_stream.pvs` provides incremental SHA-256 and SHA-512 for signatures that hash several buffers. It reuses the compression functions above, keeps the selected width in the state type and encodes the final bit length with fixed-width counters. Keep cumulative messages below the FIPS input limits of 2⁶⁴ bits for SHA-256 and 2¹²⁸ bits for SHA-512. The SLH-DSA ACVP cases exercise both streaming variants.
