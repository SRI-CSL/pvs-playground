# RSA signatures and key establishment

`rsa_primitive` uses the shared 32-bit limb Montgomery implementation. Inputs are big-endian, odd, full-bit-width moduli of 256–2,048 octets. Digest identifiers, mask-generation selection, salt-length limits, padding, public-exponent checks and representative ranges are explicit in the theories. `rsa_encoding` covers EMSA-PSS, canonical EMSA-PKCS1-v1_5 and EME-OAEP. `rsa_random` obtains PSS salt, OAEP seeds and RSASVE candidates through the shared C attachment. RSASVE samples each candidate independently and returns failure if the bounded attempt count is exhausted. [FIPS 186-5 §5](https://doi.org/10.6028/NIST.FIPS.186-5) · [RFC 8017](https://www.rfc-editor.org/rfc/rfc8017)

`rsa_kas` completes the KAS1 and KAS2 participant operations using a one-step SHA-256 KDF and a length-prefixed FixedInfo profile. KAS1 uses a 32-octet nonce. KAS2 places U’s secret first for both participants. The shared `pairwise_confirmation` library implements a 256-bit HMAC-SHA-256 confirmation key and 128-bit tags, with ordered participant identifiers, ephemeral values and optional text. Each protocol must bind the parameters and the agreed identity encodings to the transaction. [SP 800-56B Rev. 2 §§5–9](https://doi.org/10.6028/NIST.SP.800-56Br2)

Run `python3 validation/check.py rsa rsa-private rsa-kas`. The offline RSA signature fixture contains 18 records, one per sampled group. The full non-randomized-message projection contains 51 cases. PSS checks reconstruct the encoding with NIST’s salt and recover it independently with the RSA public exponent. The private fixture includes a published RSA decryption example and two independent RSA key pairs. The fixture generator uses Python integer exponentiation, SHA-256 and HMAC to compute OAEP ciphertext and agreement expectations. The tests cover success, wrong labels, changed messages, out-of-range inputs, failed draws and bounded retries.
